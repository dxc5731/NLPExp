## 3. 本地怎样计分

每个方法先独立预测同一批原始句子，再分别与同一份金标准比较。方法之间比较的是这样算出的指标；BERT 输出不能充当 CRF／词典的正确答案。

### 实体级主指标

天池正文明确采用实体级 F1；作者公开的 Task1 评估代码按同一句内的“类型、起点、终点”精确匹配，并汇总实体计数。

- TP：类型和起止位置都正确的预测实体。
- FP：没有精确匹配金标准的预测实体。
- FN：没有被正确预测出来的金标准实体。
- `P = TP / (TP + FP)`；`R = TP / (TP + FN)`；`F1 = 2TP / (2TP + FP + FN)`。

全体句子先汇总 TP／FP／FN，再计算整体 micro-P／R／F1；不是先算每句话的 F1 再取平均，也不是五类实体 F1 的简单平均。零分母的处理也应在程序中明确。

教学用虚构例子：标准实体为“呼吸困难／Symptom”，预测成“困难”即边界错；即使类型正确，也产生一个 FP 和一个 FN。类型错同样不能算正确。同一词在不同位置出现，按不同实体实例计算。

### 课程还要求真正的逐 token 指标

本数据的 BIO 是字符级，因此对应到原句字符，比较每个位置的预测 BIO 与正确 BIO。要写清是否包含 `O`、采用 micro 还是 macro 等汇总方式；BERT 的子词先映射回原句字符，`[CLS]`、`[SEP]`、padding 不进入评价。

作者脚本打印的 `token-level metric` 调用了 `seqeval` 的实体指标，不能直接拿来充当逐字符分类指标；需要另外计算。若汇总时排除 `O` 这一类别，也不能先删除 gold=O 的字符，否则 O→实体的误报会漏算。

本轮统计 dev 有 441,339 个字符，其中 O 为 369,500 个。全部预测 O 可得到约 83.7225% 字符准确率，但实体 F1=0。这只是退化预测的算术诊断，不是训练成绩；不能只拿 accuracy 评价 NER。

## 4. 你的评估职责怎样形成可查证的产出

评估程序与交接约定可以提前准备，真实方法比较在同学交付预测后开展。以下是证据整理与工程流程说明，不替团队确定参数、比较假设和正式实验设置：

1. **预测交接**：同一数据版本、同一评估记录、相同 ID 和原句字符坐标；每种方法交预测文件、模型／配置标识及运行信息。
2. **先校验后评分**：检查记录完整性、重复／额外 ID、标签数量、11 种合法标签、BIO 连续性及长句截断后的覆盖。
3. **统一计算**：整体实体 micro-P／R／F1、五类实体分别的 P／R／F1 与实际实体数量；另算逐字符指标。各方法使用同一评价和异常处理规则。
4. **保留错误材料**：输出可定位的对话 ID、句子 ID、金标准与预测，供成员逐例复核、归因。错误现象与成因需要区分；例如发现漏检不等于已经证明原因是未登录词。
5. **结果可复算**：保留原始预测、评价输出、配置、依赖／随机种子、数据版本和耗时；关键数字能回到对应运行。可用文件哈希把本地文件与平台提交关联起来。

课程明确要求：基线对比、指标口径清楚、至少一组参数对比、至少三类错误归因；报告还要求至少三个失败样例逐一归因，以及至少三个课程原理点有自己实验的证据。成本与延迟是评分中明确强调的拉开分差点。逐类指标、错误明细和文件哈希是帮助落实这些要求的技术建议，不能声称教师逐字要求了这些文件名或字段。

具体参数对比、正式实验设计和结果解释由成员自行完成；任务书第九节禁止 AI 代写实验设计与结果分析。

## 5. 天池额外需要准备什么

使用选定版本对**完整官方 test** 做推理；不能把 dev 预测改名上传。预测文件严格命名为 `IMCS-V2-NER_test.json`，UTF-8 JSON，结构如下（虚构格式示意，不是实际测试记录）：

```json
{
  "dialogue_id": {
    "sentence_id": "O B-Symptom I-Symptom"
  }
}
```

- 第一层为原始对话 ID，第二层为原始 sentence_id。页面特别提醒 sentence_id 可能不连续，不得重新编号。
- 值是空格连接的 BIO 字符串，一个原句字符一个标签，标点和原始空白也需对齐。无实体句子仍需输出对应长度的全 O。
- 覆盖模板全部 811 段、32,935 句；标签仅为 O 和五类实体各自的 B-/I-，共 11 种。不能混入 PAD 或特殊 token。
- 只做 Task1 可以只提交这一份文件，不需要额外做其他任务，也不需要伪造其零分文件。

ZIP 必须直接包含预测文件，中间不套文件夹：

```text
submission.zip
└── IMCS-V2-NER_test.json
```

平台正文要求使用其给出的 ZIP 压缩方式，并特别强调解压后不能有中间目录。官网的完整多任务压缩命令中，只保留本任务即可：`zip submission.zip IMCS-V2-NER_test.json`。Windows 上不能默认系统已安装该命令；届时需实际检查压缩包的内部路径。

官网建议初次提交前运行官方格式检查器。相关文件本项目已有查证副本；在包含检查器及数据文件的工作目录中，公开命令对应为：

```text
python -X utf8 format_checker_IMCS_V2_NER.py IMCS-V2-NER_test_raw.json IMCS-V2-NER_test.json IMCS-V2_test.json
```

第一个参数是原始空模板的改名副本，第二个是预测，第三个是官方 test 原句。不要覆盖原始下载包。检查器还依赖同目录的 `format_checker.py`。公开代码不完整检查 BIO 连续性及额外记录，所以格式通过后仍需自己严格校验，不能把它当作模型质量评分器。
