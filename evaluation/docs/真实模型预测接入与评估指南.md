# 真实模型预测接入与评估指南

第三阶段工程交付，2026-10-17。适用 IMCS-V2-NER / Task1；Python 3.10+、标准库、普通 CPU。当前只有人工工程验证，没有真实模型成绩。无需修改 Python 源码，接入时只需准备文件并编辑 JSON 清单。

## 1. 队友交付与存放

每种方法、每次运行交一个独立目录，建议放在项目 `results/<method>/<run_id>/`。例如 `<仓库目录>/evaluation/results/bert_a/run_001/`；此真实队友目录目前是待替换示例，尚无预测。

```text
run_001/
  predictions_dev.json
  run_info.json
  config/  实际配置、必要的源码快照或未提交补丁
  logs/    实际推理、训练或词典构建日志
```

预测仍遵循[交接规范](预测结果交接规范.md)：双层原始 ID，每个原始 Unicode 码点一个严格 BIO 标签，单个 ASCII 空格分隔，11 标签，覆盖完整 dev。不要交特殊 token 标签、改编号或裁剪后的句子。不需复制巨大权重；保留 checkpoint 定位信息。

`run_info.json` 的机器可读模板为 [configs/run_info.example.json](../configs/run_info.example.json)。这是**待填写模板**，不是已执行记录；null、占位版本、路径、种子和哈希必须据实替换，未知信息保留缺失并补交。模板中 dev 文件与原包哈希已核验。源 JSON 重排、重新序列化会改变字节哈希，请使用原包原始字节。

## 2. 运行信息如何填写与核查

路径均相对 `run_info.json` 所在目录，可改为绝对路径。文件引用通常是 `{"path":"config/inference.json","sha256":"实际64位十六进制哈希"}`。用 PowerShell 计算文件哈希：

```powershell
(Get-FileHash -LiteralPath 'C:\待替换实际目录\predictions_dev.json' -Algorithm SHA256).Hash.ToLowerInvariant()
```

字段要点：

- `run_id`、`method.name` 必须与清单一致；同方法不同轮次用不同 ID。推荐 `method.kind` 为 `bert`、`crf`、`dictionary_rules`。
- `data` 填同一平台版本、划分、源文件和哈希。评分传 ZIP 时 `source_file` 是精确成员路径 `IMCS-V2-NER/IMCS-V2_dev.json`；传解压 JSON 时改为该本地文件路径。源 JSON SHA 必须对应评分输入，`archive_sha256` 保留原包来源。版本字段全组统一，不能每人随意命名。
- `prediction` 填实际文件及最终字节哈希。`code` 可用 Git revision + 布尔 dirty；dirty=true 或无 Git 时提供实际源码快照／补丁及哈希。clean Git 的 revision 存在性与实际运行版本仍需人工核对。
- `config` 有版本及文件+哈希，或完整非空 `inline` 字典；`logs` 为非空文件引用数组，可用字符串路径，提供哈希时必核对。文件存在不等于内容充分。
- `environment` 为 `{"python":"实际版本","packages":{"框架名":"实际版本"}}`，纯标准库规则可用空 packages。记录真实设备、命令、工作目录、计时范围与实测非负秒数。
- BERT 的 `alignment` 建议按模板分成 tokenizer、character_mapping、special_tokens、long_text 四个非空字段。旧版文字描述仍可接收，但完整性标记人工复核。校验 PASS 不证明子词映射忠实。
- BERT／CRF 需 `training`，含实际命令、模型版本、训练源文件引用及哈希、配置及哈希、日志。`random_seeds` 是实际整数种子字典，例如键 python、numpy、torch，数值不能猜填。当前完整平台训练约定以 train 为声明来源；如小组以后改变正式数据协议，先明确新协议，再更新接入规则，不能悄悄绕过核查。
- 训练集词典也提供 `training` 构建记录。完全确定性的构建可令 random_seeds=null 并填写 seed_applicability。完全没有训练／词典构建的固定规则可令 training=null，同时填 training_applicability 与 seed_applicability。

核查结果逐项为 PASS、FAIL、NEEDS_REVIEW 或 NOT_APPLICABLE。`automated_status=PASS` 仅表示程序可检查的字段、文件、哈希和一致性齐全；真实运行总体通常仍为 **NEEDS_REVIEW**。实际使用了哪个模型、是否泄漏、映射是否忠实、训练能否复现和耗时真伪须由小组核实，不能由 JSON 自证。

比较表默认不展示尚未经人工核实的推理耗时。人工确已核对日志和计时范围后，可增加 `manual_review`，包含 timing_verified=true、reviewer 和 record（人工复核记录文件的 path/sha256）；程序只核对声明及证据文件，不证明计时事实。不要为填表制造核实声明。

## 3. 配置清单与一条命令

在评估模块根目录运行一次复制（已有正式配置时直接编辑，避免覆盖）：

```powershell
Set-Location -LiteralPath 'evaluation'  # 从仓库根目录进入；已在模块目录时跳过
if (Test-Path -LiteralPath 'configs/evaluation_runs.json') { throw 'Config exists; edit it instead of overwriting.' }
Copy-Item -LiteralPath 'configs/evaluation_runs.example.json' -Destination 'configs/evaluation_runs.json' -ErrorAction Stop
```

用编辑器打开 `configs/evaluation_runs.json`。删除尚未收到的 runs，仅保留已到文件，替换方法名、ID、预测和元数据路径。配置范例已含三条；**这些队友文件尚不存在**。例如只收到第一个 BERT 时可使用：

```json
{
  "schema_version": "1.0",
  "purpose": "model_evaluation",
  "data": {"path": "../data/IMCS-V2-NER.zip", "split": "dev"},
  "output_dir": "../results/batches",
  "runs": [
    {
      "run_id": "bert_a_run_001",
      "method_name": "BERT_A",
      "predictions": "../results/bert_a/run_001/predictions_dev.json",
      "run_info": "../results/bert_a/run_001/run_info.json"
    }
  ]
}
```

这是路径格式示例，不能声称预测已生成。JSON 中 Windows 路径用 `/`，或将反斜杠写成 `\\`。清单内所有相对路径（包括 output_dir）相对**清单文件父目录**，不是 shell 当前目录。命令行 `--output-dir` 覆盖值相对 shell 当前目录。不要把输出设在原始数据目录或输入文件路径下。

完整的一键评估命令：

```powershell
python -X utf8 src/run_evaluation_batch.py --manifest configs/evaluation_runs.json --csv-bom
```

自动完成输入校验、严格评分、错误导出、运行信息核查、可比性筛查、比较表和最终落盘计数自检。无需逐一运行各脚本；一个方法也可运行，不必等人齐。后续加入更多 runs 再运行，保留各轮独立结果，不自动挑最高 F1。

每次新建 `results/batches/<时间_随机后缀>/`。返回码：SUCCESS=0、PARTIAL_SUCCESS=2、FAILURE=1。部分成功时请阅读总报告，不把非零返回码理解成所有运行均失败。全局清单无法解析／输出不可写时，控制台报错，可能无法创建总报告；合法清单中的每条运行失败都会记录。

## 4. 在哪里看结果

```text
<批次目录>/
  batch_report.json
  runs/001/ （依清单顺序编号，不依方法名字拼路径）
    run_status.json
    evaluation.json 或 rejection.json
    reproducibility_check.json  （成功评分时）
    errors/
      entity_errors.csv
      entity_matches.csv
      error_candidates.csv
      error_summary.json
  comparison/
    model_comparison.csv
    entity_type_comparison.csv
    comparison.json
```

- 总体 F1：控制台、比较总表，或每次 `evaluation.json` 的 `entities.micro.f1`。P/R、原始 TP/FP/FN、五类 `per_type` 保留完整精度。`characters` 有 accuracy、逐标签、含 O／排除 O micro/macro 及混淆矩阵。定义沿用[统一评分说明](统一评分说明.md)，本轮不改变算法。
- `entity_errors.csv` 仅 FP/FN，`entity_matches.csv` 单列 TP；都有原始 ID、运行身份、类型、Unicode 码点 `[start,end)`、字符索引、记录 ID 和输入哈希。`error_summary.json` 逐类／总体计数必须与评分完全相同。
- `error_candidates.csv` 先关联同跨度不同类，再关联同类重叠不同边界；仅双方唯一候选时一对一关联，歧义保留未关联。剩余记录为疑似漏检／误检。关联只辅助找差异，边界／类型错仍各计 FP 和 FN；不是失败根因。
- 多模型总表为 `model_comparison.csv`；五类表为 `entity_type_comparison.csv`；完整未舍入指标、评估路径及哈希在 `comparison.json`。主指标只按实体 Micro-F1 排序，不计算综合分、不自动选最佳轮次。

## 5. 校验失败与元数据未齐

`REJECTED`：查看 `rejection.json` 中 validation.errors.by_code 和 examples，按原始 ID、标签位置找缺句、长度、非法标签／BIO 等问题；交回生成预测的队友修复并重新导出。工具不截断、不补 O、不修改预测。test 无公开 gold 也明确拒绝评分。

`DEBUG_SCORED`：预测合法，技术评分和错误材料已保留，但复现信息有缺失／不一致。查 `reproducibility_check.json` 的 FAIL 项，据实补齐元数据后重跑。非关键元数据问题不会阻止技术调试，但这些结果不会无提示进入比较表。旧结果保留，不回写成成功。

比较需同划分、同金标准字节哈希、同数据版本、兼容评分政策、同类别及顺序、SCORED／校验 PASS、运行身份明确、实际预测／数据／元数据哈希一致，且自动元数据项齐全。真实比较额外要求本次固定平台 dev 的原始字节哈希；ZIP 输入还核对固定原包哈希，重新序列化的数据可调试但不能冒充原包进入正式表。缺失项列入 excluded；人工测试用途不能进入真实比较。多份原本合格但金标准／版本／政策不同，则整体 INCOMPATIBLE，不拼一张表。缺少某种方法不会阻止其他方法评分。

表中 NEEDS_REVIEW 明示人工核查未完成。COMPARED 只说明分数在上述口径下可并列，**不证明训练协议公平、无泄漏或实验已复现**。课程正式归档前补齐人工复核；配置、日志、源码快照及原交接文件应保留在原位置，后续比较会复查实际哈希。路径迁移后需重新接入，不能偷偷改旧报告。

## 6. 本地上下文与 CSV

默认所有通用表和日志不含完整医疗句子及实体文本。需要本机人工查看时显式运行：

```powershell
python -X utf8 src/run_evaluation_batch.py --manifest configs/evaluation_runs.json --csv-bom --local-text
```

仅错误句子的原文、gold／prediction 实体及文本写入各自 `errors/local_analysis/sentences.jsonl`。此目录被 gitignore 排除，但打包工具未必遵守 gitignore，课程材料／公开材料必须人工排除；也不要把原始数据、秘密、权重带入提交包。TP 表虽无原文仍是定位材料，按项目授权使用。

CSV 默认 UTF-8，`--csv-bom` 改为 UTF-8 BOM 方便 Excel。所有不可信文本单元格的公式前缀 `= + - @` 及开头制表／换行会加 `'` 防止公式执行；JSON 保留原始身份。Python 读取 BOM CSV 用 encoding="utf-8-sig"。不要删除前缀后在电子表格中执行外部内容。

## 7. 人工核实、测试与 test 接口

仓库首次检出时，先在 `evaluation/` 运行 `python -X utf8 tests/prepare_author_reference.py`，准备固定哈希的测试参考；完整官方数据验收还需按[data/README.md](../data/README.md)准备本地原包。评估命令本身不依赖作者参考或训练框架。

正式使用前由成员核对真实模型及源码版本、训练数据与无泄漏证据、配置日志内容、子词和长文本还原、种子与环境、推理计时范围及复跑结果。参数对比、三类错误归因、失败案例和课程原理证据由小组结合真实实验选择与解释；程序不代写结论。

人工三方法彩排命令（与真实结果隔离）：

```powershell
python -X utf8 src/run_evaluation_batch.py --manifest examples/pipeline_validation/evaluation_runs.json
python -X utf8 -m unittest discover -s tests -v
python -X utf8 tests/run_pipeline_acceptance.py --official-data data/IMCS-V2-NER.zip
```

最后一条可重跑分阶段及全量测试、三方法 CLI、官方 dev 只读核验，证据独立保存在 `logs/pipeline_validation/acceptance/<新目录>/`；不会生成官方数据的模型预测。详见[人工样例](../examples/pipeline_validation/README.md)和[证据索引](../logs/pipeline_validation/README.md)。

未来 `predictions_test.json` 继续沿用接口；可用第一阶段校验器对原包 test 做完整 ID、字符、BIO 校验。批量评分入口对 test 保留拒绝记录，**不产生本地效果分数**。天池最终改名、官方格式复核及 ZIP 尚未实现／执行；上传前重新查证平台入口和格式。当前不制作正式提交包。
