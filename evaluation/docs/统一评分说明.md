# 统一评分核心与验证说明（第二阶段 v1.0）

2026-10-17；仅适用 IMCS-V2-NER / Task1。实现独立的严格实体评分与真正的逐字符分类评分，普通 CPU、Python 3.10+、仅标准库。本轮所有有数值的运行均为**人工样例上的评分器验证**，不代表模型实验、方法比较或天池成绩。第一阶段输入接口仍见 [预测结果交接规范](预测结果交接规范.md)。

## 1. 严格实体级主指标

实体用 `(原始对话ID, 原始sentence_id, 实体类型, start, end)` 唯一确定。位置从 0 开始，采用**左闭右开 `[start, end)`**，单位为原句 Unicode 码点；如 `O B-Drug I-Drug O` 的 Drug 是 `[1,3)`。每个 B 新建实体，相邻同类型 B 属于不同实体。不同句子／对话的坐标不能相互匹配。

只有五项全部一致才算 TP。预测集合减去正确集合为 FP；金标准集合减去正确集合为 FN。类型错误、起点错误或终点错误均可能同时产生 FP 与 FN，不做部分匹配、文本相似度或加权。

- `P = TP / (TP+FP)`；`R = TP / (TP+FN)`；`F1 = 2TP / (2TP+FP+FN)`，后者与 `2PR/(P+R)` 等价。
- 五类各报 TP/FP/FN/P/R/F1、gold support 与预测数；全局先汇总所有实体计数，再计算 micro-P/R/F1，不平均句级 F1。
- **主指标为 `entities.micro.f1`**。`gold_total` 和 `predicted_total` 分别是金标准及预测实体总数。
- 每个分母为 0 的指标固定输出 `0.0`。即使 gold 和 prediction 都无实体，实体 F1 仍为 0，不用 1 冒充有效识别。无 NaN/Infinity。
- 文件输入必须先通过第一阶段校验；纯实体提取函数也拒绝未知标签及非法 I 转移，不隐式修复 BIO。

## 2. 真正的逐字符分类指标

一个原始 Unicode 码点是一个分类位置，与第一阶段的 Python `len(str)` 一致；空格、标点、emoji 和组合重音符各自参与统计，不归一化。预测标签直接与该位置的金标准 BIO 标签比较，特殊 token 不进入评价。

固定混淆矩阵顺序：

```text
O, B-Symptom, I-Symptom, B-Drug, I-Drug,
B-Drug_Category, I-Drug_Category,
B-Medical_Examination, I-Medical_Examination,
B-Operation, I-Operation
```

**行是真实标签，列是预测标签**。对标签 k，`TP=M[k,k]`，`FP=列和-TP`，`FN=行和-TP`，`Support=行和`。输出每个标签的计数及 P/R/F1。报告保存完整矩阵、行和与列和，可独立复核。

| 汇总 | 明确定义 |
|---|---|
| `characters.accuracy` | 全部位置的正确数／字符总数，包含 O；没有字符时为 0 |
| `characters.including_o.micro` | 11 类 one-vs-rest TP/FP/FN 求和后算 P/R/F1。在完整单标签分类中，三者均等于 accuracy |
| `characters.including_o.macro_f1` | 固定 11 类 F1 的不加权平均，缺席类也以 F1=0 计入分母 11 |
| `characters.excluding_o.micro` | 固定 10 个非 O 类的计数求和，仍使用全部位置：O→实体计 FP，实体→O 计 FN |
| `characters.excluding_o.macro_f1` | 固定 10 个非 O 类 F1 的不加权平均，缺席类以 0 计入分母 10 |

排除 O 是排除一个**标签类别**，不能删除 gold=O 的位置，否则会隐藏误报。这里不合并 B/I、不额外生成“只看实体类型”的另一种字符指标。所有指标使用统一零分母策略 0.0；JSON 保存未舍入的 0—1 比例，控制台显示六位小数。macro 是固定全类别平均，不能与“仅对出现过的类别平均”混用。

作者脚本名为 `token-level` 的部分使用 seqeval 的实体指标，未作为本工具的字符指标参考或实现依赖。

## 3. 校验、评分、拒绝与结果留存

`src/validate_predictions.py` 新增 `load_and_validate(...) → (report, data, predictions)`，复用已有读取及校验逻辑；旧 `run_validation(...)` 的报告接口和 CLI 保持兼容。评分直接用同一次读取的已校验对象，避免评分前重新读取变化的文件。

`src/evaluate_predictions.py` 只在 `validation.status == PASS` 且 split=dev 时调用评分核心。FAIL／NOT_RUN 一律不评分；test 即便结构校验通过也因无公开金标准被拒绝。未提供金标准不能返回假零分。该入口暂只支持 dev 与 test 拒绝，不提供 train 评分入口。

CLI 必须显式传 `--purpose scorer_validation`（人工／诊断）或 `--purpose model_evaluation`（真实预测）。这是记录用途的人工声明，程序不能从标签自行判断是不是模型输出，也不能自动证明不存在答案泄漏。

在 `--output-dir` 下按北京时间时间戳及随机后缀新建一个唯一子目录：

```text
<output-dir>/<YYYYMMDDTHHMMSSffffff>_<unique>/
└── evaluation.json   # 只有 SCORED 才产生
# 或 rejection.json  # 被拦截时产生；不含 entities/characters/metric_policy
```

不会覆盖上次运行，也不写回原始数据和预测。省略 output-dir 时，人工用途默认 `logs/evaluation/`，真实用途默认 `results/evaluation/`。如果输出目录是输入文件或位于传入的数据目录内则拒绝。

成功报告含 schema、用途、划分、创建时间、Python 版本、输入路径与 SHA-256（ZIP 及实际源成员、预测原始字节）、三个实现文件的哈希、完整校验报告、对话／句子／字符数、指标定义、实体指标、字符指标及时间。`timing_seconds.validation` 为加载和校验时间，`scoring` 为纯指标计算时间，`total_before_publication` 还包括映射准备等，均不包含写报告；不是模型推理或训练耗时。拒绝报告保留校验状态、错误统计与原因，但不含评分指标。

退出码：成功评分 0；输入校验 FAIL 1；NOT_RUN、test 禁止评分、参数／报告写出错误 2。报告以 `status=SCORED` 或 `REJECTED` 区分；validation 内部继续使用第一阶段的 PASS/FAIL/NOT_RUN。

## 4. 可复制命令

在评估模块根目录执行，路径含空格时加引号。

人工全流程与两阶段测试：

```powershell
python -X utf8 -m unittest discover -s tests -p test_validate_predictions.py -v
python -X utf8 -m unittest discover -s tests -p test_evaluate_predictions.py -v
python -X utf8 -m unittest discover -s tests -v
python -X utf8 src/evaluate_predictions.py --data examples/scorer_validation/data_dev.json --predictions examples/scorer_validation/predictions_dev.json --split dev --purpose scorer_validation --output-dir logs/evaluation/manual_cli
```

收到队友真实文件，假设存放于 `results/bert_a/run_001/predictions_dev.json`：

```powershell
python -X utf8 src/evaluate_predictions.py --data data/IMCS-V2-NER.zip --predictions results/bert_a/run_001/predictions_dev.json --split dev --purpose model_evaluation --output-dir results/bert_a/run_001/evaluation
```

替换预测文件实际位置即可；也可将 data 换成官方 dev 原始 JSON 或数据目录。CLI 自动先校验，无需手动重复跑两条命令。仍需按交接规范核对 run_info、固定原包哈希及真实完整规模。程序支持人工小数据，未把官方规模写死为评分条件。

只读接入官方 dev（不生成预测、不评分）：

```powershell
python -X utf8 src/validate_predictions.py --data data/IMCS-V2-NER.zip --split dev --audit-data --report logs/evaluation/data_audit_dev_20261017.json
```

## 6. 可复用接口与当前边界

- `extract_entities(tags, dialogue_id, sentence_id)`：严格 BIO → `set[Entity]`。
- `score_entity_sets(gold, predicted)`：实体集合 → 五类及 micro 计数与指标。
- `score_confusion_matrix(matrix)`：11×11 计数 → 真正字符分类指标。
- `score_sequences(gold, predicted)`：`{(dialogue_id,sentence_id): 标签序列}` → entities/characters；检查 ID、长度与 BIO。
- `evaluate(data_path, prediction_path, *, split="dev", purpose=...)`：强制完整文件校验 → 可追溯结果或拒绝，供下一阶段调用。

纯指标接口接收内存序列，不验证原始文件的 UTF-8 或覆盖；正式文件流程必须使用 evaluate。run_info 真伪、实际 tokenizer 对齐是否忠实、模型无泄漏及训练复现仍由人工／后续流程核查。当前不实现多模型比较、逐例错误导出、错误归因或提交 ZIP；正式模型及实验设置仍由小组决定，报告实验设计与结果结论由成员完成。
