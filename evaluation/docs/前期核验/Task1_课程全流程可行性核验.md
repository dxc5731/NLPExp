# Task1 能否完成 NLP 课程大作业：数据与评估可行性核验

核验日期：2026-10-15。基于课程任务书全文、天池公开规则，以及用户已下载的 NER、DAC、SR 三个压缩包。医学报告生成包未打开。本文件是选题可行性与资料核查，不包含团队实验结果，不替团队撰写正式实验设计和结果分析。

## 结论

**继续选择 Task1 / IMCS-V2-NER 合理。现有数据足以完成“数据 → 基线与 BERT → 评估 → 对比 → 错误分析 → 可复现交付”的完整课程流程。没有发现因数据缺失而必须换题的致命问题。**

但是不能把课程主评估完全交给天池：公开测试集没有金标准，平台无法替代本地逐字评估、五类实体细分、错误定位和教师复算。课程主结果应落在一份有标准答案、与训练隔离的本地评估集上；天池官方 test 用于额外的隐藏答案测试和单项榜单比较。

这个结论证明的是数据与评估协议可行，不是已经跑通 BERT/CRF，也不是分数、排名或课程得分保证。训练环境、预测对齐与端到端运行仍需要团队实现和验证。

## 1. 任务书真正要求什么

任务书总分 45，明确允许 BERT 微调作为 B 方向的主方案；不要求换成 7B 聊天模型，也不要求做多个数据集子任务。

| 课程要求 | Task1 现有材料能否支持 | 还需要团队实际完成什么 |
|---|---|---|
| 非大模型基线、主方案及对比 | 能：五类 BIO 标注足以训练词典/CRF/BERT | 独立预测与统一评估 |
| B 方向逐 token 与实体级 P/R/F1 | 能：train/dev 都有逐字 BIO 答案 | 分别实现两套明确指标口径 |
| 实验与评估分析 12 分 | 能：标签、类型、边界均可对照 | 至少一组参数比较、至少三类错误归因、真实证据 |
| 源码与可复现性 12 分 | 能：有本地金标准和可保存预测 | 固定依赖、种子、数据版本、命令、模型获取方式 |
| 至少三个原理点，以实验证据说明 | 能：可联系子词对齐、BIO/实体评价、评估协议 | 团队独立选择并拿真实证据解释 |
| 系统架构图与数据流 | 能：读取、预处理、预测、评估、展示构成完整系统 | 清晰实现与记录，不要求医疗聊天系统 |
| 真实演示与一个难例 | 能：同一句子的金标准和多方法预测可对照 | 展示真实推理和评价；非静态假结果 |
| 来源、规模、许可、清洗规则 | 能：官方页面、包和本次审计可引用 | 记录实际使用范围及清洗清单 |
| 四人贡献可核查 | 能：两人 BERT、一人基线、一人评估 | 每人代码、日志、提交记录与贡献说明一致 |

任务书没有要求“必须用数据发布者名为 test 的文件作为唯一评估集”，也没有要求榜单名次。报告要求写清测试集来源和规模，因此可以明确说明本地评估集来自哪个官方划分、如何保持独立。

“跑不通”和“报告数字无法溯源”是任务书硬门槛。比能否上榜更先要解决的是教师能否复算主要结果。

## 2. 已拿到的数据到底够不够

| 官方划分 | 对话数 | 句子数 | BIO 标准答案 |
|---|---:|---:|---|
| train | 2,472 | 98,529 | 有 |
| dev | 833 | 33,267 | 有 |
| test | 811 | 32,935 | 无 |

官方 dev 中共有 **23,578 个实体**：症状 15,351，药品名 3,115，药物类别 1,717，检查 2,316，操作 1,079。五类均有足够实例用于计算指标和查找实际错误；这是监督信息的可用性判断，不是对模型统计功效或分数的承诺。

所有 train/dev 句子的字符数和 BIO 长度一致，标注使用的 11 种标签均在官方集合中，未发现非法 I 转移。句子最大长度 199 字符，test 最大 197 字符；单句建模的数据长度本身不会强迫复杂长文本方案。但 BERT 子词数不必等于字符数，加入上下文后仍应检查长度、切窗和坐标恢复。

NER、DAC、SR 三个下载包中的 `IMCS-V2_train.json`、`IMCS-V2_dev.json`、`IMCS-V2_test.json` 和 `mappings.json` **SHA-256 全部相同**。额外包并不提供更多对话或测试金标准，主要是各任务提交模板和预测示例不同。换 DAC/SR 无法绕开测试答案隐藏问题，也没有必要为了“流程完整”同时做它们。

## 3. 测试集没答案为什么仍然可行

需要区分三个用途：训练、选参数、最终评估。文件名不是决定用途的唯一因素，是否被训练和调参用过才影响结论。

目前尚未开始训练，一条适合课程复现的路径是：

1. 在官方 train 内按**完整对话**划出内部训练和内部调参数据；具体比例和设置由团队确定。
2. 将带答案的官方 dev 保留为本地独立评估集，模型与设置确定后再统一评估。报告明确写“本地评估集来源于官方 dev，833 段、33,267 句”，不把它冒充官方 test。
3. 用同一冻结方法预测官方 test，提交天池得到独立的平台分数。

这样，课程的逐 token/实体指标、参数对比记录、错误分析与复现都能在本地完成；平台提供额外外部验证。官方 FAQ 禁止把 dev 用作训练集，这条路径符合该限制。

也可以沿用官方 train 训练、dev 调参、test 平台评价的常见流程。但若只剩平台 test 作为最终评估，拿不到其逐字金标准，就不能本地复算完整测试指标和逐例错误。对本课程而言，保留可复算的本地独立评估更稳妥。

不能在看完本地评估错误后反复改模型，还把同一集合称为“从未用于选择的最终测试”；若发生迭代，应如实说明其验证用途。冻结后分析错误是正常过程，基于这些错误继续调参会改变该集合的角色。

参数对比并不需要线上测试答案；可以在内部调参阶段得到比较证据。报告的结果表必须标注每个分数对应的划分，不能将内部验证、官方 dev 和官方 test 数字混在一列不作说明。

## 4. 已发现的坑：影响与可解性

| 问题 | 若忽略会怎样 | 可行处理 |
|---|---|---|
| 官方 test 无 BIO 答案 | 无法本地完整复算 test 指标或定位 test 错误 | 有答案的独立本地评估作课程主体，平台 test 作额外验证 |
| GitHub 原始版本与平台版标签不同 | 训练/评估版本混用、无法解释榜单差异 | 全员锁定用户下载的同一平台 ZIP 和哈希 |
| mappings.json 只有症状 BIO 映射 | 漏掉药品、药物类别、检查、操作 | 根据官方集合建立五类、11 种有效标签；PAD 仅作内部处理 |
| 作者脚本“token-level”实际调用实体库 | 交两份实体指标，却缺少课程所需逐 token 评估 | 单独做逐字符分类指标，并声明 O 与平均方式 |
| 示例预测有孤立 I，格式检查不拦截 | 不同解析器给出不同实体、分数漂移 | 保存原始输出，检查合法性；全模型使用同一明确解码/处理规则 |
| BERT 子词、特殊符号与字符坐标不同 | 多标签、漏字符、边界错位 | 恢复到原 sentence 的字符位置，特殊符号不评分、不提交 |
| train/dev 有整段文本重复 | 评估独立性受到影响 | 所有方法统一排除训练侧重复实例并记录，保留官方评估集原样 |
| 官方 test 评分服务器实现版本未知 | 无法事先保证非法 BIO 边界行为与本地逐位相同 | 固定公开脚本与标签规则，记录本地/平台口径；不宣称服务器完全开源 |
| 下载需天池账号流程 | 教师不能匿名一键获取官方包 | 提前说明申请/认证、路径、哈希；主结果不依赖教师另行打榜 |

重复对话详情：train `10189999` 与 dev `10333194`，50 句、488 字符；2 句话的标签存在差异，共 7 个字符标签不同。没有发现 train/test 或 dev/test 的整段精确重复，但未做语义近重复鉴定。原始包未修改，具体清洗策略需要团队记录。

这些问题都能通过局部、明确的工程与评估处理解决，不要求重新标注整套数据或训练新的大规模模型。它们是实施前必须确定的约定，不是换题理由。

## 5. 评估角色的工作是完整的

用户负责评估，至少涉及：

- 统一样本 ID、数据版本、字符坐标和金标准接口。
- 对词典、CRF、BERT 分别计算逐字符指标、严格实体 P/R/F1 与五类细分结果。
- 区分总体 micro 指标、类别平均指标、含 O 准确率，防止漂亮数字掩盖漏检。
- 校验预测文件，保存模型配置、数据与文件哈希、真实执行日志，生成可复算的结果表。
- 提供真实错误定位工具与对照材料，由团队解释边界、类型、漏检、误检等错误来源。
- 核查参数比较和模型比较是否基于同一口径、同一评估集合。
- 对接天池提交，保存平台分数和单项排序证据，并说明与公开方法比较的条件限制。

本次用完整 dev 标签做了计分健全性检查：将标准标签直接作为输入预测时，作者实体解析函数与计数公式得到 23,578 个 TP、F1=1；全 O 时实体 F1=0，而字符准确率为 83.7225%。这是评价程序的已知输入检查，不是模型实验结果。尚未训练词典、CRF 或 BERT。

教师复现应能重新运行模型推理并评估主要本地结果；保存预测有助于快速复算，但仅播放已保存分数不足以证明模型真实运行。权重、数据、录屏按课程要求只提供合法获取链接，不进入 ≤50MB 的课程提交包；README 说明数据准备步骤、依赖、种子、命令、预期输出及计算资源。

## 6. 平台的作用和当前事实

CBLUE3.0 当前配置到 2027-04-30。支持只提交一个 NER 预测文件的 ZIP，未提交项自动按 0；综合分为 19 项均值。页面可以点击 `IMCS-V2-NER-F1` 旁图标按单项排序。

2026-10-15 实测单项第一行为 `htcmlu / Transformer`，F1=89.2108，其他计分项全为 0，总分仅 4.6953。这证明只做 Task1 可以参与单项排名。总榜第一行则是前夜 2026-10-14 22:38:01 的提交，其 NER 为 86.8542；总榜第一不等于单项第一。

官方 test 成绩与同一版本榜单成绩可以作外部参照；本地 dev 成绩不能直接拿来宣称超过榜单 test 成绩。平台不是课程评分的必需前提，也不能保证名次或高分。
