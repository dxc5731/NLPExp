# NLPExp 本地实验演示应用使用说明

应用提供项目总览、Dev运行与评分、自定义文本识别、实验成果对比、运行记录与证据五个区域。前端读取真实文件和后端响应；完整dev只能由终端手动发起。短文本按钮调用本地冻结模型，不调用外部模型服务，不执行训练。

## 1. 分支与目录

首次准备完整项目请从仓库 **main** 分支创建独立检出。main已有 `baseline/`、`code/`、`evaluation/` 等公共依赖，本次仅增加演示应用，没有替换这些模块。

**dxc** 保留原BERT-CRF分支的文件范围，也包含同一套演示应用源码。干净检出的dxc缺少上述完整项目依赖；应使用main的完整检出，或先按项目第一阶段的增量补全流程在本地补齐依赖。不要在含私有成果的原工作区强制切换分支、清理或覆盖文件。

```text
frontend/                 React、TypeScript、Vite、Recharts
backend/                  FastAPI、推理适配与运行记录读取
scripts/run_dev_demo.py   终端全量dev推理与统一评估入口
scripts/start_demo_*.cmd  Windows启动脚本
docs/demo/使用说明.md      本文
.local/demo_app/          本机配置、冻结源码、难例（不提交）
runs/demo_runs/           每次独立的全量运行（不提交）
runs/demo_text_runs/      本地短文本记录（不提交）
```

## 2. 运行条件

- Node.js与npm；开发验收使用Node24、npm11。Windows使用 `npm.cmd`。
- 后端独立Python环境，验收为Python3.12，依赖锁定在 `backend/requirements.lock.txt`。
- 既有ML环境：验收为Python3.13.5、torch2.14.1+cu132、CUDA13.2、transformers5.20.1、tokenizers0.23.3。两个BERT短文本入口和冻结CRF全量入口需要可用CUDA；规则使用CPU。
- 三条路线的实际模型/词表、匹配Tokenizer、官方dev原JSON、冻结E5源码、训练来源记录，以及第一阶段历史评估材料。仅安装前端依赖不能生成真实预测。

已有本机环境时直接使用第4节命令。新机器可在仓库根目录创建独立后端环境，不要重建或升级已有ML环境：

```powershell
py -3.12 -m venv .local/demo_backend_env
.\.local\demo_backend_env\Scripts\python.exe -m pip install -r backend/requirements.lock.txt
Set-Location frontend
npm.cmd ci
```

ML环境必须另外按原模型复现说明准备并确认CUDA可用。后端与ML通过子进程隔离，后端环境无需再安装PyTorch。

## 3. 本机资源配置与受控资产

仓库提供 `backend/runtime.example.json` 结构示例；其中的 `C:/path/to` 与 `C:/controlled` 都是占位路径，不能直接运行。另存为 `.local/demo_app/runtime.json` 后，填写本机真实**绝对路径**。已有runtime文件时只核对，不覆盖。

| 字段 | 真实所需内容 |
|---|---|
| project_root / ml_python | 当前完整工作区与实际ML Python可执行文件 |
| dev / data_dir | 官方 `IMCS-V2_dev.json` 及其目录；833对话、33,267句、441,339字符 |
| softmax_model_dir | 匹配的bert-base-chinese配置、Tokenizer和预训练本体；原Softmax构建入口会读取它，再strict加载正式best.pt |
| softmax_checkpoint / softmax_source_run | 正式 `runs/lr5e-5_ep3_20261022-151229/checkpoints/best.pt` 及对应run ID；该run的config和训练日志也需保留 |
| crf_checkpoint / crf_training_run | 正式第三轮E5权重及原训练run目录、manifest、配置和日志 |
| crf_reproduce | 正式E5交接包 `reproduce` 的完整源码副本，包括infer.py、training_config.json和冻结源码树 |
| crf_inference_config | 同一交接包中的 `dev/config/inference.json`；其中源码哈希及模型身份用于核验 |
| original_train | 原训练JSON，仅用于记录训练输入身份，不在演示中训练 |
| stage1_audit | 包含 `rescored_dev_summary.json` 的本地审计目录，及该摘要引用的真实evaluation/prediction文件 |
| evidence | 含本机真实 `ml_environment.json` 的受控证据目录 |
| demo_runs / text_runs | 新运行输出根目录，建议分别使用 `runs/demo_runs`、`runs/demo_text_runs` |

冻结资产身份：

| 资产 | SHA-256 |
|---|---|
| Softmax best.pt | `93322262dd14252203966cd56499086430a51b13d1112aa0162fcf18b87f6adb` |
| CRF E5 epoch_0005.pt | `e5ee6aaa8d4a00a4626553002aa9a63253a8ee0139463fec2bb41427bf391bed` |
| 官方dev JSON | `16f597ad368971c7db994ca904e05d91942f0e3c73009c9ef1d597fde065d39f` |
| 原数据ZIP | `84e34d2417b839d9fbe5c5f391e44de2a9b01bd5f31d576b8feccc78c1dfbc67` |

CRF E5权重大小为1,220,509,451字节。它从完整checkpoint加载模型状态，只另读BERT结构 `config.json`，不需要另加载预训练权重本体。必须保留正式 `training_config.json` 中Tokenizer及BERT结构配置的路径布局与逐文件哈希。不能替换成第四轮边界辅助头代码。

还需要两个本地材料：

1. `.local/demo_app/verified_case.json`：由已有核验结果提供，包含id、raw_text、gold_tags、source、historical（各路线tags与原预测文件身份）。这是含真实样本文本的受控文件，未上传本仓库。只有输入与该完整原句精确一致才关联金标；不得自行编写金标。
2. `evidence/ml_environment.json`：记录实际python、packages、cuda、gpu、cuda_available，与本机环境一致；不能照抄其他设备的成功记录。

原ZIP放在项目根目录 `IMCS-V2-NER.zip`，只用于本地身份核对。规则读取 `baseline/dict/` 五类冻结词表，mc10实际应有570条候选。历史图表读取 `docs/bert_crf/analysis/four_runs_comparison.json` 和 `docs/bert_crf/figures/` 四张图。

异机复制历史材料时，原摘要中可能有绝对路径。应另存适配副本，使摘要引用真实存在的对应文件，并将runtime指向副本；保留原文件与哈希及路径差异。没有这些材料时不能宣称完成历史证据链。冻结模型权重、原始医疗文本和私有日志请通过项目成员授权的受控渠道取得，不能从本提交中获得。

## 4. 启动和终端全量实验

在项目根目录分别打开两个PowerShell：

```powershell
.\scripts\start_demo_backend.cmd
```

```powershell
.\scripts\start_demo_frontend.cmd
```

打开 http://127.0.0.1:5173 。后端地址 http://127.0.0.1:8000 ，健康检查 `/api/health`。两个服务只绑定回环地址；端口被占用时先检查自己的现有演示服务，不要结束无关进程。Ctrl+C停止对应服务。

第三个终端输入：

```powershell
.\.venv-bert-crf\Scripts\python.exe -B -X utf8 scripts/run_dev_demo.py --split dev --methods rule,softmax,crf
```

每次创建唯一 `dev_demo_日期_时间_随机串` 目录。依次执行规则mc10、正式Softmax、冻结CRF E5新预测，各自独立校验，再调用项目统一评估批处理。没有训练参数，不覆盖旧预测或报告。终端显示真实命令、阶段、日志和退出码，不显示模拟进度。

网页进入“Dev运行与评分”，勾选“自动跟随最新运行”。页面每2秒读取状态和日志，评分前本次指标显示“—”；历史分数单独显示。运行结束后可查看各路线prediction、validation、run_info、evaluation、哈希和统一比较。预览只显示前32KB，完整文件在实际输出目录，后端已登记的artifact接口提供完整文件。

退出0表示完整成功；退出2表示部分成功；退出1表示失败或中断。自动元数据PASS不等于人工公平性审阅也完成；NEEDS_REVIEW必须保留。首轮曾发现实际输入副本路径与记录路径不一致，已保留事后说明并在新目录重跑；页面读取该运行时显示说明，不修改历史记录。

## 5. 短文本识别与严格评分

进入“自定义文本识别”，输入文本后点击“运行三种方法”。后端依次调用真实模型，返回原文高亮、实体 `[start,end)`、逐字符BIO及方法差异。区间按Unicode码点计算，保留原字符、空格和标点；相同实体文字位于不同位置时不视为同一实体。

- 自由输入没有可靠金标，不显示P/R/F1或准确率。
- “载入已核验的官方难例”只读取本地受控案例文件；页面区分官方金标、历史预测与本次预测。
- 严格实体匹配要求起点、终点、类型全部相同；仅重叠不能算TP。实现复用统一评估器。
- 网页上限500个原始码点，冻结BERT另有256token限制；超限明确拒绝，不截断。
- Tokenizer跳过空格等字符时可能出现coverage_gap；失败路线显示具体原因，不删空格、不补O、不用其他方法替代。
- 模型eval、无梯度推理；检查参数前后哈希。缓存权重空闲时转回CPU；首次调用包含加载。
- 短文本记录只保存在本地 `runs/demo_text_runs`，不发第三方模型；不要将含原文的结果或日志上传公开仓库。

## 6. 录像建议

1. 终端展示项目路径、`git branch --show-current` 和 `git rev-parse HEAD`。
2. 手动输入全量CLI，展示真实模型加载、样本处理、预测输出与评分日志。
3. 切换网页查看同一run ID、当前阶段、真实日志与结束状态。
4. 查看新预测、校验报告、评分报告和SHA-256，比较本次与历史官方dev结果。
5. 打开短文本，三模型真实推理，展示高亮、BIO表和边界差异。
6. 有已核验案例时展示可靠金标与严格匹配；无金标时不演示虚构分数。
7. 展示五类实体指标与CRF四轮实验，明确内部val不等于官方dev；最后返回本次文件路径完成证据闭环。

本机已实际完成三路线全量dev重推理和统一评分，Micro-F1分别为规则76.5929%、Softmax88.0127%、CRF E5 89.3501%。这些是已完成运行的复现结果，不是每次请求的预设返回。正式test无公开金标，本应用不提供test F1。

## 7. 测试与常见问题

在已配置完整本地资源的工作区执行：

```powershell
.\.local\demo_backend_env\Scripts\python.exe -B -X utf8 -m unittest discover -s backend/tests -v
Set-Location frontend
npm.cmd test
npm.cmd run build
```

已验收后端15项、前端5项测试及生产构建；真实全量模型运行与浏览器联调另外完成。原评估器135项合成样例测试通过不代表三模型现场运行，不能混淆两类证据。

若页面读不到项目：检查runtime、stage1摘要及其evaluation引用、verified_case是否存在。若BERT失败：检查CUDA、冻结权重哈希、Tokenizer、匹配源码和token限制。若日志停在等待GPU：全量CLI与短文本共用GPU锁，录像时先完成全量再做短文本。刷新网页不会重新启动全量实验。

仓库未包含模型、原始数据、真实医疗样本文本、本机runtime、运行日志、截图、node_modules、构建输出或本地验收报告。根目录原README及忽略规则保持原样，前端自己的 `.gitignore` 排除其依赖和产物。
