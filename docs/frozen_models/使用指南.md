## 3. 环境与完整性检查

本次验证环境为 Windows x64、Python 3.13.5、PyTorch 2.14.1+cu132、Transformers 5.20.1、Tokenizers 0.23.3；GPU 为 RTX 5060 Laptop。本包统一入口要求可用 CUDA，与原 CRF 冻结入口一致。当前机器可直接复用原项目的 `.venv-bert-crf/Scripts/python.exe`，无需安装或修改原环境。

在解压得到的本包根目录执行以下命令；`python` 应指向你准备的环境：

```text
python -X utf8 verify.py
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available())"
```

首条应输出 `PASS`，第二条 CUDA 应为 `True`。新机器可在单独虚拟环境中安装：

```text
python -m venv .venv-frozen
.venv-frozen/Scripts/python.exe -m pip install "torch==2.14.1+cu132" --index-url https://download.pytorch.org/whl/cu132
.venv-frozen/Scripts/python.exe -m pip install -r requirements.txt
```

上述为 Windows 命令；安装的 PyTorch 构建须匹配机器和 NVIDIA 驱动。后面的命令使用此环境的 Python。其他系统和版本组合未在本次整理中验证。

## 4. 单句预测

以下均在本包根目录执行。中文通过 Python UTF-8 参数和文件接口处理，无需 PowerShell 管道读写中文。

```text
python -B -X utf8 infer.py --model softmax --text "孩子发烧38度，可以吃布洛芬吗？"
python -B -X utf8 infer.py --model crf --text "孩子发烧38度，可以吃布洛芬吗？"
```

终端显示模型名、原文和每个原始字符对应的 BIO 标签。需要保存时加 `--output outputs/softmax_single.json` 或 `--output outputs/crf_single.json`，同时生成 `.run_info.json`。两个模型分别执行一次命令，每次进程加载一个模型。

## 5. 文件批量预测

可直接使用包内人工例子：

```text
python -B -X utf8 infer.py --model softmax --input example_input.json --output outputs/softmax_example.json
python -B -X utf8 infer.py --model crf --input example_input.json --output outputs/crf_example.json
```

输入格式与 IMCS 原始 JSON 相同，只需对话 ID、`dialogue` 列表、字符串 `sentence_id` 和原始 `sentence`。其他字段不进入模型。预测输出为 `对话ID -> 句子ID -> 用空格连接的逐字符BIO标签`；保持原始 ID、原始字符及顺序。

推理完整 dev 或 test 时，替换 `--input` 为你自己的原始 JSON 路径。Softmax 默认 batch=64，CRF 默认 batch=16，可用 `--batch-size 8` 降低显存占用。输出文件和配套运行记录必须不存在；再次运行请使用新文件名。数据不需要复制回原项目目录，也不需要设置全局环境变量。

两者均保留原有字符映射和解码方式：Softmax 在字符还原后显式修复非法 BIO，并记录修复次数；CRF 使用字符级 CRF 严格 BIO 解码，不进行 Softmax 的修复。上限为 256 个词片，超长、字符缺覆盖或非法输入会报错，不会静默截断或补标签。

标签共 11 个：`O`，以及 `Symptom`、`Drug`、`Drug_Category`、`Medical_Examination`、`Operation` 各自的 `B-` / `I-` 标签。两份模型的标签顺序相同，但模型结构和 checkpoint 格式不同，不能互换权重文件。

## 6. 加载原理和本次验证

Softmax checkpoint 的模型参数在 `model_state` 中；入口从本地 config 构造 `AutoModelForTokenClassification`，再以 `strict=True` 加载全部冻结参数。CRF 必须使用配套的自定义 `CharacterBertCRF`、字符 Adapter 和 CRF 实现；入口使用 v1.1 的 `load_checkpoint_model` 校验模型身份及训练配置。不要把 CRF `.pt` 当成 Hugging Face 的 `save_pretrained` 目录直接加载。

`infer.py` 是本次新增的相对路径入口：没有训练步骤，模型处于 eval 模式，禁用梯度并使用 `torch.inference_mode()`；推理前后检查参数哈希与梯度。原权重及冻结模型/对齐/解码源码均逐字节复制。除固定模型参数以外，入口也核对配套源码和 Tokenizer 的哈希。

本次实际验证范围、两种模型完整 dev 的逐句逐字符对比结果、参数前后哈希和原文件复查结果，见 `packaging_validation.json`。复查采用新的独立输出目录，不覆盖原预测。本次未重新训练或调参；历史评分与本次包装验证分开记录。
