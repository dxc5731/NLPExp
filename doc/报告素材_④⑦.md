## ④ 实现细节（ltm 负责部分：公共数据 + BERT-Softmax）

### 1. 数据管线

| 环节 | 做法 | 依据/数字 |
|---|---|---|
| 切分 | 按**整段对话**切 train/val，90:10，seed=42 | 2472 段对话 → train 2225 / val 247；按句子切会让同段对话的近似句跨两边，验证分数虚高且不报错 |
| 分词对齐 | 用 tokenizer 返回的 offset 把词片映射回原始字符 | 全量 98529 句、1279361 字符：0 丢字、0 重叠、0 截断 |
| 特殊符号 | `[CLS]`/`[SEP]`/补位不参与损失 | 交叉熵忽略 -100 |
| 长句 | 最长 199 字符（201 词片），远小于 256，无需滑窗 | 关闭 truncation，超长直接报错而不是静默截断 |

**踩过的坑（最能体现工作量的一条）**：一个词片可能覆盖多个字符。实测 `"38"` 是一个词片，对应 `'3'` 和 `'8'` 两个字符；直接按首字符取标签，会把跨实体的词片标签截断。最终规则改为：
**只有当这个标签能逐字还原该词片覆盖的所有字符时才使用，否则填 -100 不参与训练，并记入歧义清单。**
全量结果：8 个词片无法无损映射（8 句、21 个字符），已逐条列出；其余 98521 句逐字还原一致。

### 2. 模型与训练

| 参数 | 值 |
|---|---|
| 预训练模型 | bert-base-chinese（21128 词表，101.7M 参数） |
| 结构 | BERT 编码器 + 11 类线性分类头（逐位置分类，无 CRF） |
| 优化器 | AdamW，weight_decay 0.01，梯度裁剪 1.0 |
| 学习率 | 5e-5，线性 warmup 10% + 线性衰减 |
| batch / 轮数 | 32 / 3 |
| max_len / dropout | 256 / 0.1 |
| 随机种子 | 42（另有 1、2 做重复实验） |

### 3. 实验与结果

| 配置 | seed 42 | seed 1 | seed 2 | 均值 |
|---|---:|---:|---:|---:|
| lr 3e-5 | 0.8859 | 0.8853 | 0.8863 | 0.8858 |
| lr 5e-5 | 0.8885 | 0.8882 | 0.8885 | **0.8884** |

（以上为内部验证集实体 F1；**dev 上最终为 0.8801**，模型选择只用验证集，dev 全程未参与。）

### 4. 工程上真实卡过的地方

| 问题 | 表现 | 处理 |
|---|---|---|
| HuggingFace 新 Xet 协议 | 镜像站返回 404，随后进程段错误 | 关闭 Xet，改用镜像的 resolve 直链下载 |
| 微软商店版 Python 的 pip 缓存 | 缓存目录不可写，`PermissionError` | 关闭缓存（`--no-cache-dir`），并用 `PIP_DISABLE_PIP_VERSION_CHECK` 避免联网自检卡住 |
| 显存被桌面程序占用 | 8G 显存里 5G 被占，只能 batch 32 | 记录在案；换 云服务器后 3 轮从 71 分钟降到 11 分钟 |
| 多进程并行训练 | 4 组并行比 3 组慢 4.3 倍（11 分钟 → 48 分钟） | 瓶颈在 CPU 分词而非 GPU；并行组数按 3 组排 |
| 服务器无 git 环境 | 推理端无法提供 git revision | run_info 里改用源码文件哈希作为代码版本标识 |

### 5. 评测口径

- 逐 token：每个位置一个分类题，报准确率与 macro-F1
- 实体级：span（起止+类型）全等才算命中，micro 汇总
- 两者都算，因为训练集 **57.6% 的句子没有任何实体**：全预测成 O 也能拿到 83% 的逐字准确率，但实体 F1 为 0

## ⑦ AI 使用声明（ltm 部分，事实清单）

**使用的工具**：DeepSeek Harness 中的编程助手（对话式）。

**AI 参与的环节**

| 环节 | AI 做了什么 | 人工做了什么 |
|---|---|---|
| 代码实现 | 起草对齐、Dataset、训练、预测、校验等模块 | 提出需求、审阅、运行、判断结果 |
| 环境调试 | 定位 pip 缓存、HF Xet、CUDA 版本等问题并给命令 | 在服务器上执行、反馈输出 |
| 实验执行 | 写训练/打包/并行脚本，记录日志与指标 | 决定实验配置、选择最终模型 |
| 文档整理 | 起草 README、接口说明、复现指南、错误分析素材 | 核对事实、修订措辞 |
| 代码合并 | 设计合并方案、解决冲突、跑复现 | 确认方案、推送、对结果负责 |

**没有让 AI 做的**：实验设计与结果分析、结论与归因、个人贡献声明。

**如何验证 AI 的输出**

1. 13 个单元测试（对齐、BIO 合法性、padding、已知歧义句回归）
2. 全量 98529 句对齐自检（0 丢字、0 重叠、0 截断）
3. 官方校验器 `validate_predictions.py`：dev 与 test 均 PASS、errors=0
4. 三颗种子重复实验，确认学习率结论不是随机波动
5. 跨机器复现：同一配置在 本地 GPU 与 云服务器上结果差 0.0006
6. 干净检出复现：从仓库导出后重跑测试与训练，结果可重复
