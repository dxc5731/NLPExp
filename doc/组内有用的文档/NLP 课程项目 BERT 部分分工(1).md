1. # NLP 课程项目——BERT 部分分工（更新版）

   **项目：IMCS21 Task1——医疗命名实体识别（NER）**

   两人分别负责 BERT-Softmax 和 BERT-CRF，独立完成模型训练与实验。由于数据集核验、标签规范及预测结果校验程序已经由其他组员完成，剩余公共数据处理任务归 BERT-Softmax 负责人。

   ## 一、成员 A：公共数据处理 + BERT-Softmax

   **1. 剩余数据处理**

   - 将官方 train 按完整对话划分为内部 train/val，固定随机种子和对话 ID 名单，供全组模型统一使用。
   - 完成 BERT Tokenizer 与字符级 BIO 标签对齐，处理特殊 Token、Padding、长句截断及字符位置还原。
   - 实现统一的 PyTorch Dataset、DataLoader 和数据加载接口，供 BERT-Softmax、BERT-CRF 共同使用。
   - 完成输入数据和标签对齐测试，确保数据能直接用于 BERT 训练。
   - 复用已有数据核验与预测校验工具，不重复开发。

   **2. BERT-Softmax 模型**

   - 基于 `bert-base-chinese` 实现 BERT + Softmax 序列标注模型。
   - 完成模型微调、内部 val 验证、最优 Checkpoint 保存与加载。
   - 完成学习率等超参数对比实验，分析 Loss、F1 与训练收敛情况。
   - 实现独立推理及字符级 BIO 预测输出，保证结果符合全组交接规范。

   **3. 交付成果**

   - 公共数据划分文件、Tokenizer、Dataset/DataLoader 及自动测试。
   - 完整的 BERT-Softmax 训练和推理代码。
   - 模型配置、Checkpoint、训练曲线、参数对比结果及运行日志。
   - `predictions_dev.json`、`run_info.json` 和格式校验通过记录。
   - 对应的 Git 提交及个人工作证据。

   ## 二、成员 B：BERT-CRF 模型与结构优化

   **1. BERT-CRF 模型**

   - 使用成员 A 提供的统一数据划分和数据加载接口。
   - 基于同一个 `bert-base-chinese` 预训练模型，独立构建 BERT + CRF 序列标注模型。
   - 实现 CRF 损失函数、标签掩码、序列解码及 BIO 合法转移处理。
   - 完成模型微调、内部 val 验证、最优 Checkpoint 保存与加载。

   **2. 模型改进与对比实验**

   - 研究 CRF 对标签序列建模和实体边界识别的作用。
   - 完成有无显式 BIO 转移约束等结构对比实验。
   - 分析不同实体类别、实体边界及非法标签序列等问题。
   - 与 BERT-Softmax 使用相同的基础实验条件，便于最终公平比较。

   **3. 交付成果**

   - 完整的 BERT-CRF 模型、训练和推理代码。
   - CRF 解码与标签约束的自动测试。
   - 模型配置、Checkpoint、训练曲线、结构对比结果及运行日志。
   - `predictions_dev.json`、`run_info.json` 和格式校验通过记录。
   - 对应的 Git 提交及个人工作证据。

   ## 三、协作与交接约定

   1. **成员 A 优先完成公共数据划分、Tokenizer 和 DataLoader，再交给成员 B 使用。** 两人可以错开工作时间，无需强制并行开发。
   2. 成员 B 不重复处理原始数据，直接使用成员 A 提供的数据接口，但独立实现和训练 BERT-CRF。
   3. 两个模型分别从相同的预训练 BERT 初始化，不使用对方已经微调的模型作为基础。
   4. 基础对比实验统一数据划分、预训练模型、随机种子、序列长度和基本训练条件；各自的改进实验单独记录。
   5. 官方 dev 不参与训练、调参或模型选择，最终模型确定后再生成完整 dev 预测。
   6. 两人都需要按照《预测结果交接规范》提供完整预测、运行信息、配置和真实训练日志，先通过统一格式校验，再交给评估负责人。
   7. 最终全组指标计算和模型比较由专门的评估成员完成；两人分别负责自己模型训练期间的内部验证、参数实验和技术分析。
   8. 各自保留真实代码、Git 提交、实验日志及测试记录，作为个人贡献证明。
